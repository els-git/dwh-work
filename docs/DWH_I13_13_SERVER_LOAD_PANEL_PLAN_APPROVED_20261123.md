# I13-13 — Индикатор нагрузки сервера для администратора

<sub>План утверждён пользователем 23.11.2026 (Н1–Н5 = A)</sub>

## 1. Задача

Требование пользователя (20.11.2026): в приложении постоянно видна нагрузка на сервер DWH — как вкладка «Performance» диспетчера задач Windows; только у администратора. Цель — видеть, как на ресурсы влияет действие пользователя, загрузка или работа помощника.

**Критерий:** у администратора в боковом меню всегда видна плашка «ЦП / память»; по нажатию — панель с графиками ЦП, памяти, дисков, сети и потребления по службам DWH; у остальных пользователей плашки нет, API им отказывает; значения совпадают с `top` / `free` на сервере.

## 2. Как устроено (предложение)

- **Сбор на сервере, без пакета БД:** API (`dwh-api`, один процесс) раз в 2 секунды читает системные файлы Linux — `/proc/stat` (ЦП всего и по ядрам), `/proc/meminfo` (память, кэш, swap), `/proc/loadavg`, `/proc/diskstats` (чтение/запись), `/proc/net/dev` (сеть), свободное место (`/`, `/var/lib/postgresql`, `/backup`), счётчики cgroup служб (`dwh-api`, `dwh-dispatcher`, `dwh-llm`, `postgresql`) — и число активных запросов PostgreSQL (`pg_stat_activity`, только количество). Ничего не пишет в базу и на диск.
- **API:** `GET /api/admin/server/load` (текущие значения и история), только `SUPERADMIN`/`ADMIN`.
- **Интерфейс:** плашка в боковом меню (ЦП и память в %, цвет по порогу); по нажатию — панель с графиками и таблицей служб. Справка — раздел для администратора.

| Н2 | Что показывать | **A** — ЦП (всего и по ядрам), память и swap, нагрузка (load average), диски (чтение/запись, свободное место трёх разделов), сеть, по службам DWH (ЦП и память `dwh-api`, `dwh-dispatcher`, `dwh-llm`, PostgreSQL), активные запросы PostgreSQL | B — только ЦП и память |

## 6. Шаг 2 — песочница (23.11.2026)

- **Сборщик:** `backend/src/dwh_api/server_load.py` — поток в процессе `dwh-api` (запуск при старте API), замер раз в 2 с, 1800 замеров (60 мин) в памяти. ЦП всего и по ядрам (занято = 100 − idle − iowait, как `top`), ожидание диска, steal; память — занято = MemTotal − MemAvailable (как `free`), кэш, подкачка; load average; диски — только физические (`/sys/block/<диск>/device`): чтение, запись, активность; сеть без `lo`; свободное место `/`, `/var/lib/postgresql`, `/backup` (раздел один раз); службы — cgroup v2 (`dwh-api`, `dwh-dispatcher`, `dwh-llm`, `postgresql@17-main` в `system-postgresql.slice`), ЦП службы — доля от всех ядер; PostgreSQL — число подключений по ролям (`pg_stat_activity`, `dwh_app` только чтение, раз в 10 с; ошибка — «нет данных», повтор через 60 с). В базу и на диск ничего не пишется; пакета БД нет; права ролей не менялись.
- **API:** `GET /api/admin/server/load[?since=<время>]` — `SUPERADMIN`/`ADMIN` (`auth.require_admin`), при обязательной смене пароля — 403. Настройки (не обязательны): `DWH_SERVER_LOAD_ENABLED`, `DWH_SERVER_LOAD_UNITS`, `DWH_SERVER_LOAD_MOUNTS`.
- **Интерфейс:** `frontend/src/ServerLoadBadge.tsx` (+ `ServerLoad.css`, `serverLoadApi.ts`, тексты `serverLoad.*` ru/en/az) — плашка под пользователем (раз в 5 с; от 70 % ▲, от 90 % ▲▲), панель поверх страницы, не блокирует страницу и чат (раз в 2 с, запрос только новых замеров; периоды 1/5/15/60 мин; подсказка при наведении); при 401/403 плашка скрывается.
- **Проверки:** тесты `backend/tests/test_server_load.py` 11/11 (разбор `/proc` и cgroup, скорости, доля служб, история, сбой PostgreSQL, доступ USER 403 / ADMIN и SUPERADMIN 200 / без сессии 401), все тесты backend OK; сборка OK, ESLint 0/0; браузер (имитация API) 14/14 — у `USER` плашки и запросов нет, у `ADMIN` плашка и опрос 5 с, панель (16 ядер, диски, сеть, службы, PostgreSQL, раздел > 90 %), опрос 2 с с `since`, подсказка, окно 60 мин, отказ API 403 скрывает плашку; замер на настоящем `/proc` песочницы совпал с `free`.
- **Документы:** справка 1.12.0 (раздел 4.5 «Нагрузка сервера», `level=ADMIN` — помощник отвечает администраторам), `DWH_ENGINES.md` 1.6.0 (раздел 9).

**Шаг 3 (выпуск `2026.11.53`, приёмка на сервере):**
1. Под администратором: плашка видна, панель открывается; под обычным пользователем — плашки нет.

4. Подтверждение пользователя → реестр, I13-13 `DONE`.
