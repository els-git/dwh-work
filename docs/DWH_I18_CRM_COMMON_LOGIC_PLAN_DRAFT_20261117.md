# I18 — Перевод CRM на общую логику источников · проект плана

<sub>Проект · 17.11.2026 · требует утверждения пользователем (решения Р1–Р9)</sub>

## 1. Цель

У источников нет особых настроек (решение пользователя 16.11.2026). CRM (`CRM_RETAIL`) загружается тем же механизмом, что и остальные источники:
- объекты и маппинг в интерфейсе;
- STG → ODS;
- заявки «Загрузки → Объекты»;
- ошибки с понятными причинами;
- витрина из конструктора (I19).

Старый контур выводится из работы без потери отчётности, ИИ-помощника, сохранённых отчётов и проверок качества.

**Критерии `DONE`:**
1. Все объекты CRM, нужные отчётности, загружаются заявками объектов (STG → ODS) без кода, особого для CRM.
2. Витрина отчётности строится конструктором витрин.
3. «Отчётность», ИИ-помощник и сохранённые отчёты работают на новой витрине с теми же цифрами за общий период.
4. Проверки качества CRM выполняются общим механизмом.
5. Старые команды и экраны CRM отключены; данные старого контура сохранены.
6. Приёмка на сервере и подтверждение пользователя.

## 5. Риски и ограничения

- **Объём CRM.** Неизвестен до шага 2. Если крупные таблицы не имеют колонки изменения, INCREMENTAL невозможен. Тогда снова решение пользователя: FULL в пределе или выборка по родителю (Р2 = B).
- **Учётная запись CRM `vtb`** имеет права записи (I13-06). Чтение защищено шлюзом `source_gateway`, задача остаётся отдельной.
- **Расписания нет** до I09: загрузка CRM — по заявкам вручную.
- **Обновление витрин после ODS** проверяется на CRM — источник доступен с сервера. Для `OPERATION_COLLECTOR` это по-прежнему ждёт I13-09.
- **История версий** заявок после переключения не пополняется (Р3 = A). Старая история сохраняется.
