<sub>24.11.2026, редакция 2 от 25.11.2026 · **утверждён пользователем 25.11.2026**: Ф1, Ф3, Ф6–Ф10 = A, Ф2′/Ф4′/Ф5′ (раздел 3.1), Ф11 = A, задача I12-07 заведена · `IN_PROGRESS`.</sub>

## 1. Задача (roadmap I12-01…I12-06)

Загружать данные из файлов JSON/XML, которые появляются в папке: снимок целиком (FULL — последний готовый файл) или все новые файлы по порядку (INCREMENTAL). Дата файла берётся из имени (`YYYY-MM-DD_HHMMSS`), а не из времени файла в ОС. Каждый файл учитывается в реестре (контрольная сумма, результат, попытки), повторно успешно обработанный файл не применяется. Чтение безопасное: только разрешённая папка, предел размера и вложенности, без внешних сущностей XML (XXE).

Утверждённые ранее правила, которые план не меняет:
- I02-02, «Защита истории», п. 6: для FILE актуальность — дата внутри имени файла; файл с той же или более ранней датой может только **добавлять отсутствующие ключи**, существующие записи не обновляет;
- I02-03, «Безопасность подключений», п. 7: отдельные минимальные права для FILE;
- I03: у источника вида `FILE` — одно подключение (`meta.source_connection.source_kind = 'FILE'` уже предусмотрен пакетом 005).

## 2. Что уже есть в коде

- Разбор ответа JSON/XML, путь к записям, раскладка вложенных полей `a.b`, подбор типов, проверка структуры и «Сохранить структуру» — `api_request.py` / вкладка «HTTP-запрос» (I11). Для файлов используется тот же разбор.
- Движок загрузки STG → ODS, история, инкремент, `SOURCE_DRIFT`, заявки, расписания, диспетчер (I06–I09, I11).
- Вид подключения `FILE` в `meta.source_connection` (005) без реализации.

## 3. Решения

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Ф1 | Откуда DWH берёт файлы | **A** — из папки на сервере DWH: корень `/srv/dwh/files`, у источника — своя подпапка (`/srv/dwh/files/<код источника>`). | Ф3 | Форматы | **A** — JSON (массив или путь к массиву), JSON Lines (строка — запись), XML (путь до элемента записи); кодировка UTF-8 (с BOM или без) | B — только JSON и XML |

| Ф8 | Защита чтения | **A** — путь проверяется после разворота ссылок (только внутри корня), предел размера файла (по умолчанию 200 МБ, `DWH_FILE_MAX_BYTES`) и вложенности (64), XML с `DOCTYPE`/`ENTITY` отклоняется (`FILE_XML_DTD_FORBIDDEN`), сторож-тест: к файлам обращается только новый модуль `file_gateway.py` | B — без предела размера |
| Ф9 | Структура и ручные поля (I12-06) | **A** — «Проверить файл» читает последний готовый файл и предлагает колонки и типы (как у API); можно добавить поле вручную по пути (`a.b.c`) с типом — для полей, которых нет в образце | B — только автоматическая структура |

### 3.1. Решение пользователя 25.11.2026 и новая редакция Ф2, Ф4, Ф5

Пользователь: «Готовность файла — его дата актуальности, и она не в названии, а внутри файла. Если дата есть и она актуальная — файл готов к приёмке». Поэтому:

| № | Новая редакция (рекомендация A) |
|---|---|
| Ф2′ | У объекта: маска имени (только выбор файлов, без даты), формат, путь к записям и **путь к дате актуальности внутри файла** (JSON — `meta.as_of`; XML — элемент `response.header.date` или атрибут `response@asOf`); формат даты — ISO 8601 (`2026-11-25`, `2026-11-25T10:00:00`), пояс по умолчанию `Asia/Baku` |
| Ф4′ | Файл готов, если он полностью читается (JSON/XML без ошибок разбора), дата по пути есть и она **актуальная** (Ф11). Если файл не разбирается и менялся меньше 60 секунд назад — считается недописанным и ждёт следующего запуска без ошибки; старше 60 секунд — ошибка `FILE_BROKEN`. Файл без даты — `FILE_NO_DATE` в реестре |
| Ф5′ | Порядок и выбор — по дате внутри файла: FULL — один файл с самой новой актуальной датой; INCREMENTAL — все готовые необработанные файлы по возрастанию даты |

Шаблон даты в имени (`YYYY-MM-DD_HHMMSS`) из roadmap I12-02 заменяется датой внутри файла — это изменение задачи I12-02 по решению пользователя.

| № | Вопрос | Вариант A (рекомендация) | Вариант B |
|---|---|---|---|
| Ф11 | Что значит «актуальная» | Дата **новее** даты последнего успешно загруженного файла этого объекта; файл с той же или более старой датой не загружается (`SKIPPED_NOT_ACTUAL` в реестре) — для файлов это заменяет правило I02-02 п. 6 («старый файл добавляет только отсутствующие ключи») | Дата **не старше N дней** от сегодняшней (N — у объекта, по умолчанию 1); старый, но допустимый файл по правилу I02-02 п. 6 только добавляет отсутствующие ключи |

## 6. Шаг 2 — опись на сервере (только чтение)

Одна команда на сервере, ничего не меняет:

```bash
ls -ld /srv/dwh /srv/dwh/files 2>&1; df -h /srv /var/lib/postgresql; id dwh; systemctl show -p User -p ProtectSystem -p ReadWritePaths dwh-api dwh-dispatcher; findmnt -t cifs,nfs,nfs4,smb3 || echo "no network mounts"
```

Что смотрим: есть ли `/srv/dwh/files`, свободное место, под кем работают службы (`dwh`), их защита (`ProtectSystem=strict` оставляет `/srv` доступным на чтение — DWH файлы только читает), есть ли подключённые сетевые папки.
