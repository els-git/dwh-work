# I23 «Витрина DM по готовому SQL-запросу» — проект плана

Статус: **утверждён пользователем 18.11.2026**: С1, С3, С5–С8 — как предложено; С2 — только `ods`; С4 — с уточнением: допустимы и составные запросы `UNION` / `UNION ALL` / `INTERSECT` / `EXCEPT` (а также `WITH`), главное — один запрос, который только читает. ID I23 и порядок «после I22» согласованы пользователем 18.11.2026; I22 `DONE` 18.11.2026.

## 1. Требование пользователя

«В ДМ должна быть возможность импортирования SQL — таким образом сформировать витрину уже по готовому запросу».

## 2. Что уже есть (проверено по коду 18.11.2026)

- Витрина — `meta.dm_mart` с версиями `meta.dm_mart_version` (018): поля `meta.dm_mart_field` (тип из белого списка, один ключ), источники `meta.dm_mart_source` (только `ods.*`), фильтры.
- Публикация из интерфейса (019): таблицу `dm.<код>` строит база по полям версии; новая структура строится рядом (`dm.<код>__next`) и подменяет старую; при удалении или смене типа поля — список затронутых отчётов и подтверждение. Строку белого списка помощника и «Отчётности» ведёт публикация.
- Движок витрин (`etl/src/dm_mart_worker.py`, роль `dwh_etl`): проверка ключа, `DELETE` + `INSERT`, журнал запусков, обновление после ODS.
- ODS читает только `dwh_etl`; `dwh_app` (API) — нет. `dwh_etl` может писать в `stg`/`ods`/`etl`, поэтому выполнять под ним чужой SQL нельзя.

## 3. Решения (на утверждение)

## 4. Пакет БД 023 (по С3–С8)

- `meta.dm_mart_version`: вид версии `BUILDER` / `SQL`, текст запроса и его SHA-256, таблицы запроса (для обновления после ODS);
- роль `dwh_dm_sql_ro` без пароля и без входа до настройки, `SELECT` на `ods`, права по умолчанию для новых таблиц `ods`, `CONNECT` — инструментом настройки;
- функции сохранения SQL-черновика и публикации (через механизм 019); журнал и заявки — те же, что у конструктора.

## 5. Шаги до `DONE`

1. Утверждение плана (С1–С8).
2. Опись: точная схема 018/019, места, которые меняет пакет (только чтение).
3. Пакет 023: E0 в песочнице → E1 → E2 (каждый переход — с разрешения); настройка роли `dwh_dm_sql_ro` на сервере инструментом.
4. Песочница: движок (чтение под `dwh_dm_sql_ro`, запись под `dwh_etl`), API (проверка, предпросмотр, сохранение, публикация), интерфейс («Витрины DM» → «Новая витрина по SQL»), справка; тесты, сквозная проверка, браузер.
5. Выпуск, приёмка на сервере: витрина по запросу к `ods.app_retail_*`, обновление после ODS, просмотр в «Отчётности», запрос с записью или к другой схеме — отказ.
6. `DONE` после подтверждения пользователя.

## 6. Не входит

Запросы к источникам напрямую (только `ods`), хранимые процедуры, параметры в запросе, расписание.

## 7. Шаг 2 — опись (18.11.2026, только чтение кода)

Что затронет пакет 023 (018/019 не переписываются целиком — только перечисленное):
- `meta.dm_mart_version` (018/019): новые колонки — вид версии `kind` (`BUILDER` по умолчанию / `SQL`), `sql_text`, `sql_sha256`, `sql_tables text[]` (таблицы `ods` из `EXPLAIN`); ограничение «у `SQL` есть текст и хотя бы одна таблица, у `BUILDER` — нет текста».
- `meta.dm_mart_field` (018): подходит без изменений — поля SQL-версии (имя, тип из белого списка, одна колонка-ключ) хранятся там же; DDL строит `meta.mart_builder_ddl` (019) без изменений.
- `meta.dm_mart_version_problems` (018): для `SQL` проверять только поля и ключ (у SQL-версии нет источников `GRAIN`/…) — замена функции с разветвлением по `kind`.
- `app.mart_builder_preview` / `app.mart_builder_publish` / `meta.mart_builder_plan` (019): подходят без изменений — публикация, построение рядом (`__next`), подмена и подтверждение при удалении/смене типа колонок работают по полям версии.
- `etl.dm_mart_enqueue_after_ods` (018): добавить обновление SQL-витрин, у которых таблица ODS есть в `sql_tables`.
- Новое: функция сохранения SQL-черновика `app.dm_mart_sql_version_save` (`ADMIN_INTEGRATION_MANAGE`; текст, таблицы и поля передаёт API после проверки под `dwh_dm_sql_ro`), функция для движка — прочитать текст опубликованной/собираемой SQL-версии (`dwh_etl`); роль `dwh_dm_sql_ro` (без пароля, `SELECT` на `ods` и права по умолчанию для новых таблиц `ods`, владелец которых — `dwh_admin`, создатель таблиц `ods` с 021).
- Код: движок `etl/src/dm_mart_worker.py` — ветка `SQL` (чтение под `dwh_dm_sql_ro`, `COPY` в `dm.<код>` / `__next` под `dwh_etl`, проверка ключа); API `dm_builder_admin.py` — проверка, предпросмотр, сохранение; интерфейс `DmBuilderPanel.tsx` — «Новая витрина по SQL»; инструмент настройки роли (пароль в `/etc/dwh/dwh.env`, `CONNECT`) по образцу `dwh_ai_setup.py`.

Дальше — шаг 3: пакет 023, E0 в песочнице.
