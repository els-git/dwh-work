# I09 — Расписание загрузки отдельного объекта

<sub>Проект плана, 23.11.2026. Итерация начата решением пользователя 23.11.2026.</sub>

## 1. Задача

Сейчас объект загружается только вручную: «Загрузки» → «Объекты» → «Запустить» создаёт заявку `etl.object_run_request` (пакет 015), диспетчер на сервере (`dwh-dispatcher`, опрос раз в 5 с) выполняет STG → ODS, затем витрины (I19). I09 добавляет **расписание у отдельного объекта**: диспетчер сам создаёт заявку в назначенное время.

Задачи roadmap: I09-01 — каталог расписаний с часовым поясом и защитой от наложения запусков; I09-02 — экран создания, изменения, включения и отключения; I09-03 — в истории видно, ручной запуск, плановый или повторный, дублей нет.

Согласованные ранее правила (roadmap, раздел 1.2): расписание и ручные запуски — **вне «Администрирования»** (в «Загрузках»); сохранение настроек и публикация **не запускают** загрузку; ручной запуск не включает расписание. Групповые расписания — I15, не в v1.

## 2. Что известно по коду (до описи)

- Очередь: одна активная заявка на объект (уникальный индекс `object_run_request_active`) — повторная заявка, пока идёт загрузка, невозможна; это и есть защита от наложения.
- Виды заявки: `RUN` (по стратегии версии), `CONTINUE_ODS`, `FULL_RERUN`; заявку создаёт пользователь (`requested_by_user_id` обязателен).
- Диспетчер — `tools/server/dispatcher_service.py` → `etl/src/run_request_dispatcher.main()` под `dwh_etl`.
- Кода и таблиц расписаний в git нет; есть ли остатки старого механизма CRM в базе — покажет опись.

## 3. Решения (на утверждение)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| П1 | Сколько расписаний у объекта | **A** — одно (включено / выключено) | B — несколько |
| П2 | Как задаётся время | **A** — формой: «каждые N минут» (от 15), «каждые N часов», «ежедневно в ЧЧ:ММ», «по дням недели в ЧЧ:ММ» | B — строка cron |
| П3 | Часовой пояс | **A** — один, `Asia/Baku`, показывается в форме | B — свой у каждого расписания |
| П4 | Кто запускает | **A** — диспетчер: на каждом цикле проверяет наступившие расписания и создаёт заявку `RUN` с пометкой «по расписанию» | B — отдельный таймер systemd |
| П5 | Объект уже грузится в момент запуска | **A** — запуск пропускается и записывается как «пропущен: идёт загрузка»; следующий — по расписанию | B — ждать окончания и запустить сразу |
| П6 | Сервер был выключен, время прошло | **A** — после включения один запуск вместо всех пропущенных | B — пропущенные не запускать |
| П7 | Повтор после ошибки | **A** — настраивается: 0–3 повтора через 5–60 мин; в истории — «повтор №N» | B — без повторов в v1 |
| П8 | Вид загрузки по расписанию | **A** — `RUN` (по стратегии версии) или `FULL_RERUN` (периодическая полная — ограничение I07) — выбирается в форме | B — только `RUN` |
| П9 | Где на экране | **A** — «Загрузки» → новая вкладка «Расписания» + в «Объектах» колонка «Расписание» (следующий запуск); права — как у ручного запуска | B — только колонка в «Объектах» |
| П10 | Кто записан автором плановой заявки | **A** — пользователь, включивший расписание; вид запуска — `SCHEDULED` / `RETRY`; события в журнале аудита | B — служебный пользователь |

## 4. Шаги до `DONE`

1. **Опись** на сервере (только чтение): `database/diagnostics/i09_schedule_inventory.sql` — часовой пояс, остатки старых расписаний, колонки и ограничения очереди, длительность загрузок, права функций очереди.
2. **Утверждение** П1–П10.
3. **Песочница:** пакет 032 (таблица расписаний, функции настройки для `dwh_app`, функция «наступившие расписания → заявки» для `dwh_etl`, вид запуска и номер попытки в заявке; откат), E0; диспетчер, API, вкладка «Расписания»; тесты, сборка, ESLint 0/0, браузер, сквозная проверка с ускоренным временем.
4. **Выпуск, E1 и E2 пакета 032** на сервере (каждый — с разрешения пользователя).
5. **Приёмка на сервере:** расписание «каждые 15 минут» на объекте `PROCESS_VIEWER` — два плановых запуска `SUCCESS`; наложение — пропуск записан; отключение — запусков нет; ручной запуск не меняет расписание; в истории видны «вручную / по расписанию / повтор». Реестр; подтверждение — `DONE`.

## 5. Не входит

- Расписания групп и зависимости объектов (I15).
- Расписания витрин отдельно от объектов (витрины обновляются после ODS, I19).
- Календари праздников.
