# I02-06 — Аудируемый отзыв старых привязок `CRM_RETAIL` без профиля (G8)

<sub>Проект плана · 20.11.2026 · на утверждение пользователя</sub>

## 1. Задача и критерий

Roadmap I02-06: «Аудируемый отзыв двух старых `ACTIVE` привязок `CRM_RETAIL` от 28–29.10.2026 (G8)». Критерий: **происхождение выяснено; отзыв записан в журнал `secret_store` и аудит.**

## 2. Что известно (20.11.2026)

По `dwh_secret_check.py` на сервере (выпуск `2026.11.50`) у `CRM_RETAIL` три привязки без профиля, созданные до пакета 005:

| Ссылка | Состояние | Создана | Итог CREATE |
|---|---|---|---|
| `60890348…` | `PENDING` | 28.10.2026 16:04 | `FAILED` |
| `b6518bd1…` | `ACTIVE` | 28.10.2026 17:26 | `SUCCEEDED` |
| `5d15fd24…` | `ACTIVE` | 29.10.2026 14:55 | `SUCCEEDED` |

- Их создал изолированный контур I02-03 октября (модули `secret_*` от 22–28.10, удалены 20.11.2026, Р4 = B), до появления профилей (002), актора и `key_id` (003). Записи журнала 28.10 в roadmap повреждены (`?????`), поэтому подробности берутся из базы (шаг 2).
- **Пароль по ним не выдаётся никому:** оба пути чтения (API — `app.integration_source_secret_read_begin`, ETL — `etl.source_secret_read_begin`) берут только привязку с профилем `SOURCE`; `READ` без профиля запрещён и правилом журнала (003). Действующий пароль `CRM_RETAIL` — привязка `f7b78c7d…` (профиль `SOURCE`, ключ `K2026_04`).
- **Файлов у них на сервере нет:** в `/var/lib/dwh/secrets` только файлы привязок с профилем (опись I02-03 сверяет `ACTIVE` с файлом только для профильных).
- Отозвать можно только функциями журнала: `secret_store.begin_operation('REVOKE', …)` → `finish_operation(…, true)` (пакет 004; путь G8 проверен тестом 004 F20). `EXECUTE` на них нет ни у одной роли — вызвать может только владелец (`dwh_admin`), то есть SQL-пакет. Кнопка «Отозвать учётные данные» в интерфейсе их не касается: она отзывает только привязку с профилем `SOURCE`.

## 3. Решения (на утверждение)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Р1 | Что отзывать | **A** — все три: две `ACTIVE` и `PENDING` с неуспешным CREATE (до пакета 004 такие `PENDING` не закрывались автоматически) | B — только две `ACTIVE`, как в тексте задачи; `PENDING` останется и будет давать `WARN` |
| Р2 | Чем | **A** — пакет 027: разовая аудируемая операция через функции 004 (E0 → E1 → E2, как остальные пакеты), маркер — функция `secret_store.legacy_bindings_revoked()`; отзыв необратим, откат `.down.sql` снимает только маркер, данные — из копии `pre-027` | B — разовый SQL от `dwh_admin` без E1 на копии |
| Р3 | Актор в журнале | **A** — `actor_kind = DWH_USER`, `actor_ref = I02-06.package-027` (поле допускает буквы, цифры и `_.:-`); в аудите — `SECRET_STORE_LEGACY_REVOKE` с `create_operation_id`, ссылкой и датой решения пользователя | B — новый вид актора `OPERATOR` (изменение ограничения 003 — лишний пакет) |
| Р4 | Файлы отозванных привязок на диске (`WARN` «5 файлов REVOKED») | **A** — не трогать в I02-06 (их копирует ночная служба, удаление — отдельным решением) | B — удалять файлы отозванных привязок в этой задаче |
