# I13-15 — Имена объектов в журнале аудита

<sub>План утверждён пользователем 23.11.2026 (И1–И5 = A). Задача заведена решением пользователя 23.11.2026 (способ A). Опись снята 23.11.2026 (раздел 2.1).</sub>

## 1. Задача

При приёмке I13-14 пользователь заметил: в «Администрирование» → «Журналы» → «Журнал аудита» в колонке «Объект» показан тип и номер (`SOURCE_OBJECT: 24`, `SOURCE_SYSTEM: 9`), не видно, что именно запускалось. События хранят только `entity_type` и `entity_key`; имени в событии нет.

**Способ A (решение пользователя 23.11.2026):** имя подставляется **при показе** из справочников; записи журнала не меняются (неизменяемость I13-14 сохраняется). Известное следствие: после переименования объекта (I03-05) старые события показывают текущее имя; номер остаётся рядом.

**Критерий:** в колонке «Объект» для загрузок, заявок, паролей источников, витрин и пользователей видно имя и номер (например, `PROCESS_VIEWER · public.services (#24)`); фильтр «Объект» находит события по части имени; прочие события показываются как раньше; таблицы и права журнала не меняются.

## 2. Что известно по коду (до описи)

Функции базы пишут события с такими типами объектов (`audit.log_security_event`, пакеты 010–029): `SOURCE_OBJECT` (30 мест), `SOURCE_SYSTEM` (18), `DM_MART` (13), `DM_ENTITY` (2), `USER_ACCOUNT` (1), `AUDIT_LOG` (2). Кроме того, журнал пополняют механизмы, созданные до git (вход, пользователи, роли — `trg_audit_user_account` и др.): их типы и форму ключей покажет опись.

Пакет 029: `app.audit_log_page` (`SECURITY DEFINER`, владелец `dwh_admin`) — читает справочники `meta`/`app` без новых прав.

## 3. Решения (утверждены 23.11.2026: И1–И5 = A)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| И1 | Вид в колонке «Объект» | **A** — `<имя> (#номер)`, тип — подсказкой при наведении; в подробностях — тип, номер и имя отдельно | B — отдельная колонка «Имя» |
| И2 | Какие объекты получают имя | **A** — 5 типов с номером (раздел 2.1): `SOURCE_OBJECT`, `SOURCE_SYSTEM`, `DM_MART`, `DM_ENTITY`, `USER_ACCOUNT`; `AUTH_SESSION`, `RUN_REQUEST` и типы с текстовым ключом — как сейчас | B — только `SOURCE_OBJECT` и `SOURCE_SYSTEM` |
| И3 | Объект удалён (I03-05) или витрина помечена удалённой | **A** — строки нет: только номер с пометкой «удалён»; витрина с `deleted_at`: имя с пометкой «удалена» | B — только номер |
| И4 | Фильтр «Объект» | **A** — ищет и по номеру/ключу (как сейчас), и по части имени | B — только по номеру |
| И5 | Где строится имя | **A** — в базе, новый вариант `app.audit_log_page` (пакет 031, поле `entity_name`); API и экран только показывают | B — в API отдельными запросами справочников |
