# I17-10 — Доработка ИИ-помощника: разбор ошибок загрузок, память диалога, сворачивание

<sub>Проект плана · 18.11.2026 · ждёт утверждения пользователя (решения Р1–Р7)</sub>

## 1. Требование пользователя (18.11.2026)

1. **Разбор ошибок загрузок** по журналам ошибок и запусков — коротко, по существу, быстрее.
2. **Память диалога** — последние 10 сообщений, включая контекст снимка экрана.
3. **Сворачивание чата вместо закрытия:** ответ готовится в фоне, о готовности — всплывающее уведомление; значок «×» заменён значком сворачивания.

## 2. Что есть сейчас (проверено по коду 18.11.2026)

- Помощник (`backend/src/dwh_api/ai_assistant.py`): `/api/ai/help` (справка, снимок экрана) и `/api/ai/report` (отчёт по `dm`). Каждый вопрос — **без истории**: модель получает только текущий вопрос.
- Модель одна (`dwh-llm`, контекст 16 384 токена) и отвечает на один вопрос за раз — длинная подсказка = медленный ответ.
- Ошибки загрузок `dwh_app` уже читает: `etl.v_integration_error` (экран «Загрузки → Ошибки и история», `/api/etl/errors`, право `ETL_VIEW`), состояние объектов `etl.v_object_load_status`, витрин `etl.v_dm_mart_status`. Ошибки содержат код, поле, число строк, до 5 значений (`bad_value`) и ключи (`diagnostic_context`, I13-08). **Пакет БД для чтения не нужен.**
- Окно чата (`frontend/src/AiAssistantPanel.tsx`) висит на всех экранах; «×» прячет окно, но запрос продолжает идти — ответ приходит незаметно для пользователя.
- Журнал помощника `app.ai_request_log`: виды `HELP`, `REPORT`, `SAVED_REPORT`, `MART_VIEW` (ограничение в БД — новый вид требует пакета).

## 3. Решения (на утверждение)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Р1 | Как разбирать ошибку | **A** — сначала **мгновенная карточка без модели** по справочнику кодов (что значит код, поле, сколько строк, примеры, что сделать — по-русски, az, en); затем модель **коротко** дописывает объяснение (до ~300 токенов, без поиска по справке — так быстрее) | B — только модель (медленнее, ответ появляется через 1–2 мин) |
| Р2 | Откуда начинается разбор | **A** — кнопка «Разобрать с помощником» у ошибки в «Загрузки → Ошибки и история» и у объекта / витрины с последним запуском `FAILED` («Объекты», «Витрины»); чат открывается с разбором | B — ещё и свободный вопрос в чате «почему упал applicant?» (нужно угадывать объект по тексту — менее надёжно) |
| Р3 | Права | Разбор доступен при `AI_ASSISTANT_USE` **и** `ETL_VIEW` (то же право, что экран ошибок). Клиент передаёт только номер ошибки / объекта; текст ошибки сервер читает сам под `dwh_app` | — |
| Р4 | Значения данных в разборе | **A** — модели передаются те же сведения, что видит пользователь на экране ошибок: поле, правило, число строк, до 5 значений и до 10 ключей. Модель — только на сервере (`127.0.0.1`); в журнал помощника значения не пишутся (только номер ошибки) | B — только код, поле и число строк, без значений (объяснение беднее) |
| Р5 | Память диалога | **A** — история хранится в браузере (на вкладке) и отправляется с вопросом: последние **10 сообщений** (вопросы и ответы, каждое до 2 000 символов); сервер обрезает и сам не хранит. Снимок экрана **не пересылается заново** — в памяти остаётся ответ модели о нём (повторная передача картинки замедляет каждый ответ). Справка ищет разделы по текущему и предыдущему вопросу; отчёт получает прежний вопрос и прежний SQL («а теперь по месяцам»). Кнопка «Новый диалог» очищает память | B — история на сервере (таблица, пакет БД, доступна с другого компьютера) |
| Р6 | Сворачивание и уведомление | **A** — «×» заменяется на «—» (свернуть); запрос продолжается; при готовности, если окно свёрнуто, — всплывающее уведомление на странице «Ответ готов — открыть» и точка на кнопке «Помощник»; «Стоп» работает и в свёрнутом виде через уведомление | B — ещё системное уведомление браузера (нужно разрешение браузера; на HTTPS с временным сертификатом может не работать) |
| Р7 | Журнал разборов | **A** — без пакета БД: разбор пишется видом `HELP`, в сообщении — «разбор ошибки №…» / «объект …» | B — новый вид `LOAD_ERROR` (пакет 024: замена ограничения вида, E0/E1/E2) |

## 4. Шаги до `DONE` (при рекомендациях — без пакета БД)

| Шаг | Содержание | Режим |
|---|---|---|
| 1 | Утверждение плана (Р1–Р7) | решение пользователя |
| 2 | Песочница: справочник кодов ошибок (ru/az/en), API разбора `POST /api/ai/load-error` (по `error_id` / объекту / витрине), память диалога в `/api/ai/help` и `/api/ai/report`, кнопки «Разобрать с помощником», сворачивание и уведомление, «Новый диалог»; справка; тесты, сквозная проверка, браузер | песочница |
| 3 | Выпуск, приёмка на сервере: разбор настоящей ошибки из «Ошибок и истории» (карточка сразу, объяснение модели); уточняющий вопрос по справке и по отчёту с памятью; снимок экрана и вопрос о нём следующим сообщением; сворачивание во время ответа и уведомление; реестр | сервер |
| 4 | Подтверждение пользователя — I17-10 `DONE` | решение пользователя |

При Р7 = B добавляется пакет 024 (E0 → E1 → E2, каждый переход с разрешения) между шагами 2 и 3.

## 5. Не входит

Автоматическое исправление ошибок и перезапуск загрузок помощником; память между вкладками и компьютерами (при Р5 = A); голос; разбор ошибок источников, которых нет в журнале DWH.
