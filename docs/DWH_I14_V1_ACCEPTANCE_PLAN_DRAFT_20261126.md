## 2. Что уже есть

- **БД (PostgreSQL):** весь путь из интерфейса — подключение и пароль (I03/I04), снимок структуры, маппинг STG/ODS и публикация таблиц (I05, I06-05, I18), FULL/INCREMENTAL (I07), ручной запуск (I08), расписание (I09), порции больших таблиц (I21). На сервере работают `PROCESS_VIEWER` `public.app_users` (по расписанию) и `public.services`. У `PROCESS_VIEWER` есть ещё не настроенный объект `public.audit_log` («нет опубликованного маппинга»).
- **API (I11):** принят 24.11.2026 на `PV_API` / `api.services` — импорт cURL, JSON с курсором, XML с номером страницы, инкремент, `429`, хост не из списка, неверный секрет, расписание; с I13 — проверка полей по страницам.
- **Файлы (I12):** приняты 25.11.2026 на `PV_FILES` — LATEST/ALL_NEW, повтор, копия, опоздавший, без даты, битый, большой, XML, отказ DTD, JSON Lines, предупреждения, расписание.
- **CRM:** с адреса `10.1.57.2` CRM `10.30.58.64:5432` **недоступен** (20.11.2026, доступ пока не нужен — решение пользователя). Загрузки `CRM_RETAIL` и витрины на их ODS на сервере сейчас не проверить.
- **Откат:** выпуск — `dwh_update.py --rollback-to` (проверен в I16 13.11.2026); копии базы — `dwh_backup.py` с `--verify-restore` (проверен в I16); у каждого пакета 001–036 — откат, проверенный в E1.
- **Проверки базы:** у каждого пакета есть check (только чтение под `dwh_app`), но единого прогона «всё сразу» нет; check старых пакетов после новых даёт ожидаемые отклонения (например, check 005 — 10/11 после 006).
- **Безопасность:** вход локальный и домен (I20), сессии и права, роли базы с минимальными правами (I13-03, пакет 036), журнал аудита неизменяем (I13-14), SecretStore принят (I02-03), TLS УЦ (I13-10), интернет закрыт (I13-11). Независимой проверки не было.

## 3. Решения

| № | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| Р1 | Объект для I14-01 | **A** — новый объект `PROCESS_VIEWER.public.audit_log` с нуля только через интерфейс: снимок → маппинг STG (INCREMENTAL, если в таблице есть поле времени, иначе FULL) → публикация (таблица создаётся) → ODS → «Запустить» → повтор без изменений → расписание → запуск по расписанию; **B** — повторить путь на уже настроенном `public.services` (новыми версиями) | **A** |
| Р2 | Объём I14-03 (API) и I14-04 (файлы) | **A** — засчитать приёмку I11 и I12 (записи в реестре 12.67/12.69–12.71) и на текущем выпуске сделать короткую регрессию на тех же объектах: API — FULL и инкремент `api.services`, файлы — LATEST, ALL_NEW, повтор без дублей, файл другой структуры → `SOURCE_DRIFT`; **B** — повторить все сценарии I11 и I12 заново | **A** |
| Р3 | Регрессия CRM (I14-05) при закрытом доступе к CRM | **A** — в I14 CRM не загружать: проверить, что объекты и витрины CRM не сломаны (публикации, витрины `cdp_clients`/`crm_applicants_sql` пересобираются из имеющегося ODS), а загрузку CRM записать ограничением v1 до открытия доступа; **B** — попросить администраторов открыть доступ к CRM до приёмки I14 и прогнать загрузку `CRM_RETAIL` | **A** |
| Р4 | DB-проверки и «rollback продемонстрирован» (I14-05) | **A** — новый инструмент только чтения `tools/server/dwh_v1_check.py`: службы, выпуск, TLS, таймер копий, `dwh_secret_check`, check последних пакетов по областям с ожидаемым числом, зависшие заявки и запуски, свежие ошибки по видам — итог `V1_CHECK_RESULT`; откат — откат выпуска на предыдущий и возврат + `dwh_backup.py --verify-restore` последней копии; **B** — без нового инструмента, только существующие проверки по одной | **A** |
| Р5 | I14-07 — внутренний аудит и независимый пентест | **A** — I14-07 делится: внутренний аудит в I14 (план и границы на утверждение, проверка кода и сервера, отчёт с находками по степени риска, исправления — каждое с вашим решением, повторная проверка); независимый пентест — внешняя команда, которую организуете вы, новой задачей с новым ID (по вашему согласию) после I14; **B** — I14 не закрывается до отчёта внешнего пентеста | **A** |
| Р6 | Отметка «v1» | **A** — выпуск v1 = текущий выпуск сервера на момент приёмки; в реестре раздел «Состав v1» (что работает, ограничения: Oracle, CRM, большой объём на сервере), тег `v1.0` в git на коммит этого выпуска; **B** — только документы, без тега | **A** |
