# I13-13 — Индикатор нагрузки сервера для администратора

<sub>Проект плана · 23.11.2026 · на утверждение пользователя</sub>

## 1. Задача

Требование пользователя (20.11.2026): в приложении постоянно видна нагрузка на сервер DWH — как вкладка «Performance» диспетчера задач Windows; только у администратора. Цель — видеть, как на ресурсы влияет действие пользователя, загрузка или работа помощника.

**Критерий:** у администратора в боковом меню всегда видна плашка «ЦП / память»; по нажатию — панель с графиками ЦП, памяти, дисков, сети и потребления по службам DWH; у остальных пользователей плашки нет, API им отказывает; значения совпадают с `top` / `free` на сервере.

## 2. Как устроено (предложение)

- **Сбор на сервере, без пакета БД:** API (`dwh-api`, один процесс) раз в 2 секунды читает системные файлы Linux — `/proc/stat` (ЦП всего и по ядрам), `/proc/meminfo` (память, кэш, swap), `/proc/loadavg`, `/proc/diskstats` (чтение/запись), `/proc/net/dev` (сеть), свободное место (`/`, `/var/lib/postgresql`, `/backup`), счётчики cgroup служб (`dwh-api`, `dwh-dispatcher`, `dwh-llm`, `postgresql`) — и число активных запросов PostgreSQL (`pg_stat_activity`, только количество). Ничего не пишет в базу и на диск.
- **API:** `GET /api/admin/server/load` (текущие значения и история), только `SUPERADMIN`/`ADMIN`.
- **Интерфейс:** плашка в боковом меню (ЦП и память в %, цвет по порогу); по нажатию — панель с графиками и таблицей служб. Справка — раздел для администратора.

## 3. Решения (на утверждение)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Н1 | Кому видно | **A** — уровням `SUPERADMIN` и `ADMIN` (как остальное администрирование, без пакета БД) | B — отдельное право (пакет БД) |
| Н2 | Что показывать | **A** — ЦП (всего и по ядрам), память и swap, нагрузка (load average), диски (чтение/запись, свободное место трёх разделов), сеть, по службам DWH (ЦП и память `dwh-api`, `dwh-dispatcher`, `dwh-llm`, PostgreSQL), активные запросы PostgreSQL | B — только ЦП и память |
| Н3 | Частота | **A** — сбор каждые 2 с; плашка обновляется раз в 5 с, открытая панель — раз в 2 с | B — 5 с везде |
| Н4 | История | **A** — последние 60 минут в памяти API (видно, что было до открытия панели; после перезапуска API история начинается заново) | B — только пока панель открыта (в браузере) |
| Н5 | Где | **A** — плашка в боковом меню под пользователем, панель поверх страницы | B — отдельная вкладка в «Администрировании» |

## 4. Шаги до `DONE`

1. Утверждение Н1–Н5 (ID I13-13 — согласие пользователя 23.11.2026).
2. **Песочница:** сборщик и API, плашка и панель (тексты ru/en/az), тесты (разбор файлов `/proc`, права), сборка, ESLint 0/0, браузер; справка; `DWH_ENGINES.md` (эксплуатация).
3. **Выпуск и приёмка на сервере:** плашка у администратора и её отсутствие у обычного пользователя; значения совпадают с `top`/`free`; видна нагрузка помощника во время ответа. Реестр; подтверждение — `DONE`.
