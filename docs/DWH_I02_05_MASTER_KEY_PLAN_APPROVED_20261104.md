**Требования:** K01–K10 (roadmap, раздел 7, утверждены 28.10.2026).

## 1. Зачем

Сейчас мастер-ключ (`K2026_02`, синтетический) лежит открытым текстом в `.env`:
- его видит любой, кто может прочитать `.env`;
- резервной копии нет: 04.11.2026 ключ `K2026_01` пропал при ручной правке `.env`, и зашифрованные им файлы больше не расшифровать;
- ротации нет: на сервере может быть только один ключ.

## 2. Что получится в итоге

1. Ключ хранится в файле, зашифрованном Windows DPAPI для учётной записи, под которой работает backend. Открытого ключа нет ни в `.env`, ни в проекте, ни в git.
2. При создании ключа сразу делается **резервная копия**: файл, зашифрованный паролем резервной копии (его знает только администратор). Копия хранится отдельно от ПК и от резервных копий PostgreSQL.
3. Из резервной копии ключ **восстанавливается** одной командой; совпадение проверяется по несекретному отпечатку.
4. На сервере может быть **несколько ключей** (связка ключей): новые записи шифруются действующим ключом, старые файлы остаются читаемыми своим ключом, пока на них есть ссылки.
5. Папка ключей и папка хранилища закрыты правами Windows: доступ только у этой учётной записи, SYSTEM и администраторов.
6. Есть инструкция (runbook): создание, резервирование, восстановление, ротация, вывод старого ключа.

## 3. Решения для утверждения

| № | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| Д1 | Где хранить ключ | **A.** Файл DPAPI (CurrentUser) в отдельной папке вне проекта; **B.** оставить `.env` и добавить только резервную копию | **A**: ключ не лежит открытым текстом, случайная правка `.env` его не затронет. Компонент DPAPI уже есть (`secret_dpapi_crypto_provider.py`) |
| Д2 | Резервная копия | файл, зашифрованный паролем копии (AES-256-GCM, ключ из пароля через scrypt); пароль не хранится нигде на ПК | так; место хранения копии (флешка, сетевая папка и т. п.) выбирает пользователь, вне проекта и вне копий БД |
| Д3 | Ротация | новый ключ становится действующим; учётные данные источников переводятся на него операцией «Заменить» (REPLACE); старый ключ удаляется только когда на него нет действующих привязок | так; отдельной автоматической перешифровки нет |
| Д4 | Синтетический `K2026_02` и его файлы | вывести из `.env` после перехода; файлы оставить до вывода ключа | так |

Учётная запись: backend на ПК запускается под пользователем Windows, поэтому DPAPI CurrentUser подходит. Служебная учётная запись для сервера — вне I02-05 (эксплуатационный сервер).

## 6. Ограничения выбранной схемы

- DPAPI CurrentUser привязан к учётной записи Windows: при смене пользователя или потере профиля ключ восстанавливается только из резервной копии.
- Пароль резервной копии потерян вместе с ПК — ключ не восстановить; это осознанное условие K05.
- Администратор Windows на этом ПК может действовать от имени пользователя; защита от администратора ПК не входит в задачу.
