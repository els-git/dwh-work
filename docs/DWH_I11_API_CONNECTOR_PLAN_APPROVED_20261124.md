# I11 — Источник API (HTTP, cURL, постраничная выдача, JSON/XML)

<sub>План утверждён пользователем 24.11.2026: А1–А4, Б1–Б11 = A, задача I11-05 заведена; тестовый сервис — только для таблицы `public.services` (решение пользователя). Итерация выбрана пользователем 24.11.2026.</sub>

## 1. Задача

Сейчас DWH грузит только из баз PostgreSQL. I11 добавляет источник **API**: объект — это HTTP-запрос, ответ (JSON или XML) превращается в строки и дальше идёт общим путём: маппинг → STG → ODS → витрины, ручной запуск и расписание (I08, I09).

Модель, утверждённая пользователем 03.11.2026 (I03): у источника API есть **только название**; адрес, параметры и учётные данные хранятся **у каждого объекта**, даже если они повторяются. Правило 05.11.2026: исходящие запросы DWH к источникам — **только `SELECT` и `GET`**.

Задачи roadmap:
- I11-01 — HTTP-запрос объекта: адрес, параметры, заголовки, авторизация; секреты на сервере; безопасная проверка запроса.
- I11-02 — импорт и экспорт cURL без выполнения команд оболочки, токены скрыты.
- I11-03 — постраничная выдача, повторы, таймауты, ограничение частоты, ошибки HTTP.
- I11-04 — разбор структуры JSON/XML, путь к массиву, ручные поля и типы; тот же редактор маппинга; версии структуры и остановка при изменении структуры.

**Новое (запрос пользователя 24.11.2026):** чтобы проверить API на настоящих данных, сначала нужен **тестовый API-сервис для `PROCESS_VIEWER`**. Предлагается задача **I11-05 «Тестовый API-сервис PROCESS_VIEWER»** (ID — с согласия).

## 2. Что известно по коду (до описи)

- Контракт адаптеров (`backend/src/dwh_api/connector_contract.py`) уже допускает вид источника `API`; адаптер есть только у PostgreSQL.
- Подключение источника — `meta.source_connection`; в базе вид ограничен `DATABASE`/`FILE`. Для API подключения на уровне источника нет (по модели I03).
- Пароли хранит SecretStore: привязка `secret_store.binding` относится к **источнику** (слот `SOURCE`), привязки к объекту нет — для токена объекта нужен пакет БД.
- Версии настроек объекта — `meta.object_config_version` (пакет 008): поля, ключ, стратегия; HTTP-запроса там нет.
- Шлюз `source_gateway` закрывает только подключения к PostgreSQL; HTTP-шлюза (только `GET`) нет — его планировали вместе с I11.
- Библиотек HTTP в серверном наборе нет (`deploy/requirements-server.txt`); хватит стандартной библиотеки Python (`urllib`, `http.client`, `xml.etree`, `json`).
- `PROCESS_VIEWER` — PostgreSQL `10.1.10.40:5432`, база `process_viewer`, учётная запись `dwh_reader` только на чтение; объекты `app_users`, `services`, `draft` (у двух есть маппинг).

| Б6 | Постраничная выдача | **A** — нет / номер страницы и размер / смещение и лимит / курсор из ответа / ссылка «следующая» из ответа или заголовка `Link`; предел страниц на запуск | B — только номер страницы |
| Б7 | Таймауты, повторы, частота | **A** — таймаут 30 с; до 3 повторов на `429`, `5xx` и сетевые ошибки с паузой по `Retry-After` или нарастающей; пауза между запросами (по умолчанию 0); понятные коды ошибок `HTTP_401`, `HTTP_429`, `API_TIMEOUT`, `API_BAD_JSON` | B — без повторов |
| Б8 | Структура JSON/XML | **A** — «Проверить запрос» берёт первую страницу, пользователь выбирает путь к массиву (`data.items`, для XML — путь к элементу), вложенные поля раскладываются в `a.b`, вложенные массивы — текстом JSON; типы предлагаются, пользователь правит; дальше — существующий редактор маппинга; снимок структуры сохраняется, исчезновение поля или смена типа при загрузке — остановка `SOURCE_DRIFT` | B — только плоский JSON |
| Б9 | Инкремент | **A** — как в I07: поле изменения в ответе + параметр запроса с отметкой (`updated_since={{watermark}}`) и перекрытием; иначе — полная загрузка | B — только полная |
| Б10 | Защита исходящих запросов (HTTP-шлюз) | **A** — только `GET`; только `https` (и `http` лишь для адресов из списка); адрес — только из списка разрешённых хостов в настройках сервера (`DWH_HTTP_ALLOWED_HOSTS`); переход на другой хост по перенаправлению запрещён; предел размера ответа; сторож-тест, как у `source_gateway` | B — любые адреса |
| Б11 | Создание источника и объекта | **A** — источник вида «API» в «Администрировании» без подключения; объект API добавляется вручную (имя объекта = код запроса), снимок «из базы» для него не нужен | B — объект создаётся из импорта cURL |
