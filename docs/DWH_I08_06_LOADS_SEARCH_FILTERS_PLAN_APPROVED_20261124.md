# I08-06 — поиск и фильтры на «Загрузки» → «Объекты» (план утверждён)

<sub>24.11.2026 · утверждён пользователем 24.11.2026 (Ф1–Ф4 = A) · `IN_PROGRESS`.</sub>

## 1. Задача

Список объектов на вкладке «Загрузки» → «Объекты» растёт (CRM — 19, `PROCESS_VIEWER` — 3, `PV_API` — 2 и т. д.), нужного объекта не найти без прокрутки. Нужны поиск и фильтры.

## 2. Что известно по коду

- `frontend/src/LoadsObjectsPanel.tsx` получает **весь** список одним запросом `GET /api/integrations/loads/objects` (`ObjectLoadStatus`: источник, схема и объект, версии STG/ODS, статусы и ошибки последних запусков, последняя заявка) и расписания `GET /api/admin/integrations/object-schedules`.
- После запуска и по «Обновить» список перечитывается целиком.
- Объектов десятки, не тысячи — отбор в браузере без изменений API и базы.

## 3. Решения

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Ф1 | Где отбирать | **A** — в браузере по уже полученному списку; backend, API и база не меняются | B — параметры отбора в API |
| Ф2 | Какие фильтры | **A** — строка поиска (источник, схема, объект, таблица STG/ODS; без учёта регистра); «Источник» (список); «Состояние последнего запуска»: все / успешно / с ошибкой / выполняется или в очереди / не запускался; «Расписание»: все / включено / нет или выключено (только тем, кто видит колонку расписания) | B — только строка поиска |
| Ф3 | Сохранять ли выбор | **A** — выбор не сбрасывается после запуска и «Обновить»; запоминается в браузере пользователя (при закрытии вкладки и повторном входе остаётся), кнопка «Сбросить» | B — сбрасывается при уходе со вкладки |
| Ф4 | Что видно пользователю | **A** — над таблицей «Показано N из M»; если ничего не найдено — строка «Нет объектов по условиям отбора» | B — без счётчика |

«С ошибкой» — последний запуск STG или ODS `FAILED`; «выполняется» — последняя заявка `QUEUED`/`CLAIMED`/`RUNNING`; «не запускался» — нет ни одного запуска STG.

## 4. Шаги до `DONE`

1. **Утверждение** Ф1–Ф4.
2. **Песочница:** фильтры в `LoadsObjectsPanel.tsx`, тексты ru/en/az, справка (раздел «Загрузки»); сборка, ESLint 0/0, тесты backend (справка), браузер — отбор, счётчик, сохранение после «Обновить» и запуска.
3. **Выпуск и приёмка** на сервере: поиск по `services`, фильтр по источнику `CRM_RETAIL`, «с ошибкой», «расписание включено», «Сбросить»; затем подтверждение — `DONE`.

Пакета БД нет. Реестр — после приёмки.

## 5. Не входит

Сортировка по колонкам, постраничный показ, фильтры на других вкладках («Запуски», «Ошибки и история», «Витрины») — отдельными задачами по решению пользователя.

## 6. Шаг 2 — песочница (24.11.2026)

- `frontend/src/LoadsObjectsPanel.tsx`: строка поиска (источник, схема, объект, `схема.объект`, таблицы STG/ODS; без учёта регистра), «Источник», «Последний запуск» (успешно / с ошибкой / выполняется или в очереди / не запускался), «Расписание» (только при праве запуска), «Сбросить», «Показано N из M», строка «Нет объектов по условиям отбора». Отбор — в браузере по уже полученному списку; выбор хранится в `localStorage` (`dwh.loads.objectFilters`, чтение и запись в `try/catch` — без хранилища фильтры живут до закрытия страницы). Запросы к API не изменились.
- «С ошибкой» — последний запуск STG или ODS `FAILED`; «выполняется» — активная заявка (`QUEUED`/`CLAIMED`/`RUNNING`) — проверяется первой; «не запускался» — нет запуска STG.
- `LoadsPage.css` — полоса фильтров переносится, на ширине телефона без горизонтальной прокрутки; тексты ru/en/az (`loads.filter.*`); справка 1.17.0 (2.1).
- Проверки: сборка OK, ESLint 0/0, тесты backend 440 OK; браузер `scratchpad/i0806/ui.cjs` 19/19 (имитация API: 5 объектов трёх источников — поиск, источник, 4 состояния, расписание, «ничего не найдено», сохранение после «Обновить», после запуска и при повторном открытии, «Сбросить», ширина телефона).
