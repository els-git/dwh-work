Статус: **проект, 26.11.2026**, ждёт утверждения пользователем (решения А1–А4).

Основание: план I14 (`docs/DWH_I14_V1_ACCEPTANCE_PLAN_APPROVED_20261126.md`), Р5 = A — в I14 делается **внутренний** аудит; независимый пентест внешней командой — отдельной задачей с новым ID после I14 (по согласию пользователя).

Критерий I14-07 (roadmap): план и границы утверждены; отчёт с находками по степени риска и доказательствами; критические и высокие устранены или приняты пользователем; повторная проверка исправлений.

## 1. Что проверяется

| № | Область | Что смотрим | Как |
|---|---|---|---|

| Б2 | Права в API | каждый маршрут `/api/*` требует нужный уровень или право; пользователь с минимальной ролью не получает чужие данные и действия | опись маршрутов из кода + отрицательные запросы |

| Б4 | Внедрение SQL | весь SQL, собираемый из настроек (маппинг, ODS, витрины, SQL-витрины, отчёты помощника): кавычки идентификаторов, параметры значений | код, тесты на враждебные имена в песочнице |
| Б5 | ИИ-помощник | обход проверки SQL (`ai_sql_guard`), выход за белый список витрин и право роли, попытки «переубедить» модель | песочница с имитацией модели + несколько запросов на сервере |

| Б9 | Сервер | открытые порты, nginx и TLS, ограничения служб systemd, права файлов `/etc/dwh`, `/var/lib/dwh`, копии, SSH (вход по паролю — риск принят, I13-12) | инструмент только чтения на сервере |
| Б10 | Зависимости | известные уязвимости пакетов Python и npm выпуска | `pip-audit` / `npm audit` в песочнице по версиям выпуска |
| Б11 | Журнал аудита | значимые действия пишутся, журнал не меняется задним числом (I13-14) | опись событий + проверка по действиям Б2 |

## 2. Границы

- Код продукта во время аудита **не меняется**; каждое исправление — отдельным предложением с вашим решением (А3).
- На сервере — только чтение и отрицательные запросы тестовой учётной записью с минимальной ролью; без нагрузки и отказа в обслуживании, без перебора паролей больше 10 попыток, без изменения данных и настроек, без запросов к CRM и другим источникам, кроме тестовых (`PROCESS_VIEWER`, `PV_API`, `PV_FILES`).
- Секреты в отчёт не попадают: только факт («значение найдено / не найдено»), место и способ.
- Внешний пентест в эту задачу не входит (Р5).
