# I17-11 — Таблицы ODS в отчётах помощника

<sub>Проект плана · 23.11.2026 · на утверждение пользователя</sub>

## 1. Задача

Решение пользователя 23.11.2026 — вариант B: помощник в режиме «Отчёт по описанию» строит отчёты не только по витринам `dm`, но и по таблицам ODS. Таблицы добавляются в белый список по одной, как витрины, с правом роли. Это меняет решение I17 «только витрины» (I17-05, I17-08) по согласию пользователя.

Пример приёмки: «количество заявок за последние 2 месяца по каналу продаж», где заявки — таблица ODS `application`, канал — справочник `sales_channel`.

**Критерий:** администратор добавляет таблицу ODS в белый список помощника с правом. Пользователь с этим правом получает отчёт по ней, в том числе с соединением двух таблиц. Пользователь без права получает отказ «недоступно вашей роли». Роль `dwh_ai_ro` читает только выбранные таблицы ODS (и только разрешённые колонки). Время ответа отчёта — не больше чем вдвое дольше, чем по витрине.

## 2. Как устроено сейчас (по коду)

- Белый список `meta.ai_report_object` (пакет 016): `schema_name` ограничен значением `dm` (CHECK); у каждой строки право `required_permission_code`. Витрины конструктора попадают в список при публикации (пакет 018).
- Роль `dwh_ai_ro` читает всю схему `dm` и больше ничего.
- Проверка SQL `ai_sql_guard.py` пропускает только отношения `dm` из белого списка роли; модель получает описание всех разрешённых объектов целиком (`ai_core.describe_report_data`: колонки, справочные значения, термины, примеры).
- Экран «Администрирование» → «ИИ-помощник» сохраняет объекты только со схемой `dm` (`app.ai_report_object_save(…, 'dm', …)`).

## 3. Решения (на утверждение)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| П1 | Как таблица ODS попадает в список | **A** — администратор добавляет по одной в «ИИ-помощник» → «Объекты отчётов» (схема ODS, таблица, название, описание, право) | B — все таблицы источника сразу |
| П2 | Колонки с персональными данными | **A** — администратор может исключить колонки; исключённые колонки модель не видит, а `dwh_ai_ro` не может их читать (права на колонки) | B — таблица открывается целиком |
| П3 | Что получает модель | **A** — только объекты, подходящие к вопросу (поиск по названию, описанию и колонкам; до 4 объектов), — и для витрин тоже; иначе описание ~460 колонок ODS сделает ответ на процессоре в разы дольше | B — все разрешённые объекты, как сейчас |
| П4 | Как модель соединяет таблицы | **A** — администратор задаёт связи (`application.sales_channel_id = sales_channel.id`), модель получает их вместе с описанием | B — только через примеры запросов |
| П5 | Чтение для `dwh_ai_ro` | **A** — `SELECT` только на выбранные таблицы и колонки; права выдаёт и снимает функция базы при добавлении, изменении и отключении объекта | B — вся схема `ods`, отбор только проверкой SQL |

## 4. Шаги до `DONE`

1. Утверждение П1–П5 (ID I17-11 — согласие пользователя 23.11.2026).
2. **Опись на сервере (только чтение):** владелец таблиц `ods`, текущие права `dwh_ai_ro`, состав `meta.ai_report_object`, число таблиц и колонок ODS — скрипт `database/diagnostics/i17_11_ods_inventory.sql`.
3. **Пакет 029, E0 в песочнице:** схема `dm`/`ods` в белом списке, исключённые колонки, связи таблиц, выдача и снятие прав `dwh_ai_ro`, обновлённые функции сохранения и `app.ai_object_access`; check, тест, откат.
4. **E1 и E2 пакета 029 на сервере** (каждый — с разрешения пользователя).
5. **Код в песочнице:** проверка SQL (таблицы и колонки ODS из списка роли), описание для модели (связи, без исключённых колонок), отбор подходящих объектов, экран «ИИ-помощник» (схема, колонки, связи), справка 3.3 и 6.1, `DWH_ENGINES.md`; тесты, сборка, ESLint 0/0, браузер.
6. **Выпуск и приёмка на сервере:** добавить `application` и `sales_channel` со связью; вопрос пользователя даёт отчёт; пользователь без права получает отказ; исключённая колонка недоступна; время ответа. Реестр; подтверждение — `DONE`.

## 5. Не входит

- Таблицы STG в отчётах помощника.
- Автоматический поиск связей без указания администратором.
