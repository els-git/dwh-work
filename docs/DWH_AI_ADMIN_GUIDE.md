# Руководство: «Администрирование → ИИ-помощник»

Версия 1.2.0 · 17.11.2026 · для администраторов DWH

## 1. Что это за раздел и кому он доступен

В разделе настраивают, **какие данные помощник может использовать для отчётов** и **как хорошо он их понимает**. Там же виден журнал всех вопросов к помощнику.

- Вкладку видит пользователь с правом `AI_ADMIN_MANAGE`. У `SUPERADMIN` и `ADMIN` оно есть автоматически.
- Справку для режима «Вопрос по приложению» здесь не настраивают. Она берётся из файла справки `docs/DWH_USER_GUIDE.md` и меняется выпуском приложения.

### Права пользователей на сам помощник

Права выдаются в «Администрирование → Роли», как любые другие:

| Право | Что даёт |
|---|---|
| `AI_ASSISTANT_USE` | Кнопка «Помощник» и вопросы по приложению (справка, снимки экрана) |
| `AI_REPORT_RUN` | Режим «Отчёт по описанию» |
| `AI_ADMIN_MANAGE` | Эта вкладка и журнал запросов |

Помощник всегда учитывает права роли. Он не показывает разделы справки и витрины, которые роли закрыты, и отвечает «Текущей роли эта информация недоступна».

## 2. Как помощник строит отчёт — коротко

Когда пользователь пишет описание отчёта:

1. Сервер берёт из **белого списка** витрины, разрешённые роли пользователя.
2. Модели передаются только **описание** этих витрин: колонки, значения справочников, термины, примеры. Сами данные модель не видит.
3. Модель пишет SQL-запрос.
4. Сервер дважды проверяет запрос: по тексту и по плану выполнения. Пропускаются только чтение и только разрешённые витрины.
5. Запрос выполняется отдельной ролью только на чтение. Пользователь получает таблицу, может посмотреть SQL и скачать CSV.

Всё, что настраивается на этой вкладке, — это шаги 1 и 2: **что** модель может использовать и **насколько хорошо** она это понимает.

## 3. Белый список витрин (схема dm)

Это главный список: **помощник строит отчёты только по витринам из него.**

| Поле | Что вписать |
|---|---|
| **Имя объекта в dm** | Имя таблицы или представления в схеме `dm`, без `dm.`. Например, `v_retail_application_current` |
| **Название** | Человеческое название. Оно же показывается, когда витрина закрыта роли |
| **Нужное право** | Без этого права роль витрину не видит: модель о ней не знает, отчёт по ней не выполнится. Обычно `REPORT_VIEW` |
| **Описание для модели** | 1–3 предложения: что в витрине (одна строка — это что), какие основные показатели. Чем понятнее, тем точнее отчёты |

Кнопки в строке витрины:
- **«Изменить»** переносит строку в форму ниже. Поправьте и нажмите «Сохранить».
- **«Отключить»** / **«Включить»**: отключённая витрина пропадает для помощника у всех ролей. Удаления нет, только отключение.

Ограничения:
- Можно добавить **только объект схемы `dm`**. Таблицы STG и ODS добавить нельзя: это рабочие слои загрузки, а не отчётные. Чтобы дать помощнику данные из ODS, соберите витрину в «Администрирование → Витрины DM» и отметьте «Доступна ИИ-помощнику»: после публикации она появится в этом списке сама, с правом витрины.
- Объект должен уже существовать в базе, иначе будет ошибка «Object not found in schema dm».

## 4. Колонки-справочники

Модель не видит данных, поэтому не знает, как точно написано значение, например «Интернет-банк» или «İnternet bank». Если отметить колонку как справочник, перед каждым отчётом модель получает список её **различных значений** и пишет правильные условия `WHERE`.

| Поле | Что вписать |
|---|---|
| **Объект** | Витрина из белого списка |
| **Колонка** | Имя колонки, например `sales_channel_name_ru` |
| **Не больше значений** | Сколько значений показывать модели (1–500, обычно 50) |

Когда отмечать: колонки с небольшим набором повторяющихся значений — статусы, стадии, каналы, филиалы, продукты, валюты.

Когда **не** отмечать: номера, суммы, даты, ФИО, ИНН и любые персональные данные. Значения уходят модели в подсказку. Модель работает только на сервере DWH, но смысла в этом нет, а подсказка разрастается.

## 5. Термины

Словарь бизнес-языка: модель узнаёт, что вы имеете в виду.

| Поле | Пример |
|---|---|
| **Термин** | «Канал ИБ» |
| **Значение** | «Интернет-банк: `sales_channel_code` содержит `IB`» |
| **Объект** | Конкретная витрина или «все витрины» |
| **Статус** | Включено / отключено |

Хорошие термины:
- сокращения и жаргон: «ИБ», «ПОС», «одобренка»;
- что значит «выдан», «отказ», «активный клиент» — какими колонками и значениями это выражается;
- правила расчёта: «конверсия = число выданных / число заявок».

Чтобы изменить термин, нажмите «Изменить», поправьте поля, затем «Сохранить изменение».

## 6. Примеры вопросов с SQL

Самый сильный способ улучшить отчёты. Модель получает до 20 включённых примеров по витринам, доступным роли, и строит запросы по их образцу.

| Поле | Что вписать |
|---|---|
| **Объект** | Витрина, к которой относится пример |
| **Вопрос** | Как пользователи обычно спрашивают: «Количество заявок по каналам продаж за месяц» |
| **SQL** | Правильный запрос к этой витрине |
| **Статус** | Включено / отключено |

Как получить правильный SQL, не набирая его руками:
1. Задайте вопрос помощнику в режиме «Отчёт по описанию».
2. Если результат верный, откройте «Показать SQL» и скопируйте запрос.
3. Если не совсем верный, поправьте запрос и проверьте его через «Отчёт по описанию» или с коллегой-аналитиком.

**Важно:** при сохранении пример не проверяется. Неверный пример научит модель ошибаться. Добавляйте только проверенные запросы и отключайте устаревшие.

Когда добавлять пример:
- вопрос задают часто;
- модель ошиблась (неверный фильтр, нет группировки, не та колонка);
- в журнале запрос дважды подряд закончился ошибкой.

## 7. Журнал запросов (последние 100)

Каждый вопрос к помощнику — одна строка:

| Колонка | Смысл |
|---|---|
| **№, Время, Пользователь** | Кто и когда спросил |
| **Тип** | `HELP` — вопрос по приложению (+ «снимок экрана», если был снимок); `REPORT` — отчёт по описанию; `SAVED_REPORT` — запуск сохранённого отчёта (появится с сохранёнными отчётами) |
| **Вопрос** | Текст вопроса. **Наведите мышь — увидите SQL**, который выполнялся |
| **Статус** | Итог и код причины (ниже) |
| **Строк** | Сколько строк получил пользователь |

Строки результата отчётов и сами снимки экрана **в журнале не хранятся**. Есть только вопрос, SQL, итог и число строк.

### Статусы и коды

| Статус / код | Что произошло | Что делать |
|---|---|---|
| `OK` | Ответ получен | — |
| `OK` + `AI_REPORT_REPAIRED` | Первый запрос упал с ошибкой базы, модель исправила его сама | Если повторяется на одном вопросе — добавьте пример |
| `OK` + `AI_REPORT_TRUNCATED` | Строк больше 1000, показаны первые 1000 | Попросить уточнить описание (фильтр, группировка) |
| `NO_DATA` + `AI_HELP_NOT_FOUND` | В справке не нашлось подходящего раздела | Если вопрос частый — дополнить справку (выпуском) |
| `NO_DATA` + `AI_NO_DATA` | Модель не нашла нужных данных в доступных витринах | Нет витрины — нужна витрина `dm`; витрина есть — уточнить описание или термины |
| `DENIED` + `AI_SECTION_NOT_ALLOWED` / `AI_OBJECT_NOT_ALLOWED` | Роли закрыт раздел справки или витрина | Так и должно быть; если роль должна видеть — выдать право |
| `REFUSED` + `AI_SQL_…` | Проверка отклонила запрос модели (запись, чужая схема, несколько команд и т. п.) | Обычно разовая ошибка модели; если повторяется — добавить пример |
| `ERROR` + `AI_SQL_ERROR` | Запрос не выполнился и после самоисправления | Добавить пример с правильным SQL |
| `ERROR` + `AI_BUSY` | Модель занята другим вопросом дольше 2 минут | Подождать; при частых случаях — вопрос нагрузки |
| `ERROR` + `AI_MODEL_UNAVAILABLE` | Служба модели не отвечает | Проверить службу `dwh-llm` на сервере |
| `ERROR` + `AI_CANCELLED` | Пользователь нажал «Стоп» | — |
| `RUNNING` | Вопрос ещё обрабатывается | — |

## 8. Готовые сценарии

**Дать помощнику новую витрину**
1. Убедитесь, что витрина есть в схеме `dm`.
2. «Белый список витрин» → имя, название, нужное право, описание → «Сохранить».
3. Отметьте 3–8 колонок-справочников: статусы, каналы, продукты.
4. Добавьте термины, которые используют пользователи.
5. Задайте 3–5 типичных вопросов в «Отчёте по описанию», проверьте результат. Верные запросы сохраните как примеры.

**Помощник часто ошибается на одном типе вопросов**
1. Найдите эти вопросы в журнале и наведите мышь, чтобы посмотреть SQL.
2. Поймите, в чём ошибка: не тот фильтр — нужен термин или колонка-справочник; не та структура запроса — нужен пример.
3. Добавьте термин или пример и задайте вопрос ещё раз.

**Закрыть витрину для какой-то роли**
- Укажите у витрины право, которого у этой роли нет. Или отключите витрину для всех кнопкой «Отключить».

**Пользователь говорит «помощник не отвечает»**
- Найдите его вопрос в журнале. Статус и код из таблицы раздела 7 подскажут причину.

## 9. Чего здесь нет (и где это)

| Нужно | Где |
|---|---|
| Изменить справку по приложению | Файл `docs/DWH_USER_GUIDE.md`, через выпуск |
| Выдать пользователям права на помощника | «Администрирование → Роли» |
| Создать, изменить или удалить витрину `dm` (например, по пенсиям) | «Администрирование → Витрины DM» (конструктор): таблицы витрин создаются и меняются из интерфейса |
| Настройки модели (какая модель, потоки, время ожидания) | Сервер: `/etc/dwh/llm.env`, `/etc/dwh/dwh.env` (инструкция сервера, раздел 4b) |
