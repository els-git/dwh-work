# SecretStore — мастер-ключи: инструкция (I02-05, K10)

Все команды — Windows PowerShell 5.1, по одной, в окне, где выполнено
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`.
Скрипт: `tools\secret_key.ps1`. Он никогда не печатает ключ и пароль копии; показывает только `key_id` и отпечаток (16 символов).

## Как устроено

| Что | Где |
|---|---|
| Ключи | `%LOCALAPPDATA%\DWH\keyring\<key_id>.dpapi` — защищены Windows DPAPI для текущего пользователя |
| Зашифрованные учётные данные | `%LOCALAPPDATA%\DWH\secret_store\<secret_ref>.bin` |
| Резервная копия ключа | `<папка копии>\<key_id>.dwhkey` — зашифрована паролем копии (scrypt + AES-256-GCM) |
| Настройки в `.env` | `DWH_SECRET_STORE_DIR`, `DWH_SECRET_KEYRING_DIR`, `DWH_SECRET_ACTIVE_KEY_ID`; самого ключа в `.env` нет |

Папки `keyring` и `secret_store` доступны только текущему пользователю, SYSTEM и администраторам.
Backend должен работать под тем же пользователем Windows, который создал ключ.

## Создать ключ (с резервной копией)

```
& "C:\Users\elshad.asgarov\Desktop\DWH\dwh\tools\secret_key.ps1" -Action New -KeyId "K2026_03" -BackupDir "E:\dwh_key_backup"
```

- Пароль копии — не короче 12 символов, вводится дважды (скрытый ввод; вставка — правой кнопкой мыши).
- Папка копии должна существовать и отличаться от `keyring`. После создания перенесите копию туда, где она не пропадёт вместе с ПК (флешка, сетевая папка), и **не** кладите её рядом с резервными копиями PostgreSQL.
- Запишите отпечаток: по нему проверяется восстановление.

## Сделать ключ действующим

```
& "C:\Users\elshad.asgarov\Desktop\DWH\dwh\tools\secret_key.ps1" -Action Activate -KeyId "K2026_03"
```

Записывает в `.env` папку ключей и действующий `key_id`, удаляет старые строки с открытым ключом (`DWH_CONNECTOR_MASTER_KEY_*`). Копия `.env` без этих значений — в `runtime\backup`. Затем перезапустите backend.

## Проверить ключ и копию

```
& "C:\Users\elshad.asgarov\Desktop\DWH\dwh\tools\secret_key.ps1" -Action Verify -KeyId "K2026_03" -BackupFile "E:\dwh_key_backup\K2026_03.dwhkey"
```

## Восстановить ключ

Если файл ключа пропал или повреждён (сохранение учётных данных отвечает 503):

```
& "C:\Users\elshad.asgarov\Desktop\DWH\dwh\tools\secret_key.ps1" -Action Restore -BackupFile "E:\dwh_key_backup\K2026_03.dwhkey"
```

Отпечаток должен совпасть с записанным при создании. Перезапуск backend не нужен: ключ читается при каждой операции.
Если в связке уже есть другой ключ с тем же `key_id`, восстановление отказывает и ничего не меняет.

## Сменить ключ (ротация)

1. Создать новый ключ (`New`) с новым `key_id`, сделать копию.
2. `Activate` нового ключа, перезапустить backend. Новые учётные данные шифруются новым ключом.
3. Для каждого источника в панели «Подключение» нажать «Заменить» — рядом с состоянием появится новый `key_id`.
4. Старый ключ не удалять, пока ни один источник не показывает его `key_id` (K07). После этого его файл можно перенести из `keyring` в архив; резервную копию хранить по правилам хранения.

## Чего не делать

- Не править вручную строки SecretStore в `.env` и не удалять файлы из `keyring`.
- Не хранить пароль копии на этом ПК и в проекте.
- Не копировать ключи и `.dwhkey` в git, архивы проекта и резервные копии PostgreSQL.
- `tools\setup_connector_secret_store.ps1` отозван: он писал открытый ключ в `.env`.

## Ограничения

- DPAPI привязан к учётной записи Windows: при её смене или потере профиля ключ восстанавливается только из копии.
- Потеря и ПК, и пароля копии — ключ не восстановить.
- Служебная учётная запись и HSM/KMS для эксплуатационного сервера — вне I02-05.
