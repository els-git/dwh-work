## Находки

### Н1 — высокий: отчёт помощника читает витрины `dm` вне белого списка роли — исправляется (песочница)

**Где:** `backend/src/dwh_api/ai_sql_guard.py` (проверка SQL отчёта по описанию, I17).

**Суть.** SQL отчёта выполняет роль `dwh_ai_ro`, которая читает **всю** схему `dm` (пакет 016); ограничение «только витрины, разрешённые роли пользователя» держится только на двух проверках кода: по тексту и по плану `EXPLAIN`. Обе обходятся:
1. XML-функции PostgreSQL выполняют запрос внутри себя, и прочитанные таблицы **не видны в плане**: `schema_to_xml('dm', …)` и `database_to_xml(…)` выгружают все таблицы схемы; в списке запрещённых слов их нет (есть только `query_to_xml`, `table_to_xml`, `cursor_to_xml`).
2. Строка вида `E'\''` (экранирование обратной косой чертой) сбивает разбор строк в текстовой проверке: часть настоящего кода считается строкой и не проверяется — так проходит и запрещённое `query_to_xml(...)`.

**Доказательство (песочница, база `sec1407`, роль-владелец):**
- `check_text("SELECT schema_to_xml('dm', true, false, '') FROM dm.cdp_clients LIMIT 1", белый список = cdp_clients)` — проходит; `EXPLAIN (FORMAT JSON, VERBOSE)` показывает только `cdp_clients`; результат содержит строку из `dm.secret_mart`.
- `SELECT E'\'' , query_to_xml(chr(115)||…, true, false, chr(32)) , '' AS x FROM dm.cdp_clients` — проходит текстовую проверку, план — только `cdp_clients`, результат — данные `dm.secret_mart`.

**Кто может:** пользователь с правом `AI_REPORT_RUN` и доступом хотя бы к одной витрине; модель пишет SQL по описанию пользователя, и нужный текст можно получить прямой просьбой. Сохранённый отчёт (I17-09) хранит SQL и выполняет его так же.

**Что получает:** все строки всех витрин `dm` (на сервере — витрины CRM с персональными данными клиентов), включая выгрузку CSV.

**Не проверено на сервере** (по плану — шаг 3, тестовая учётная запись).

**Предложение исправления (на решение, А3):**
- код: запретить в тексте SQL все функции с `xml` в имени и все строки с префиксом `E`/`e` и обратной косой чертой; лучше — **белый список функций** (агрегаты, дата/время, строки, математика) вместо списка запретов;
- база (пакет 037, E0→E1→E2): `REVOKE EXECUTE ON FUNCTION` для `query_to_xml*`, `schema_to_xml*`, `database_to_xml*`, `table_to_xml*`, `cursor_to_xml*` у `PUBLIC` (их выполняют только приложения, DWH ими не пользуется) — защита не зависит от кода проверки;
- временная мера до исправления: снять право `AI_REPORT_RUN` с ролей, кроме администраторов (интерфейс «Администрирование» → «Роли»).

**Исправление (песочница, 26.11.2026):**
- `ai_sql_guard.check_text`: отклоняются строки с префиксом `E`/`U&` (`AI_SQL_ESCAPE_STRING`) и любые имена с `xml`, `ts_stat`, `ts_rewrite` (`AI_SQL_FORBIDDEN`); обычные строки с буквой «e» и `ELSE'…'` проходят; тест `test_ai_sql_guard.TextTests.test_hidden_queries_i14_07_h1`;

### Н2 — низкий: `/api/meta` отвечает без входа

`GET /api/meta` (`backend/src/dwh_api/main.py`) открыт без сессии и раскрывает имя роли базы и число объектов; считает по представлениям старого контура CRM (`meta.v_current_mapping`, `dq.v_current_rule` …), удалённого в I18, — вероятно, отвечает 500. Интерфейс его не использует (проверить). Предложение: убрать маршрут или закрыть входом.

### Н3 — низкий: нет заголовка Content-Security-Policy

`deploy/nginx/dwh.conf` ставит HSTS, `X-Content-Type-Options`, `X-Frame-Options DENY`, `Referrer-Policy`, `server_tokens off`, TLS 1.2/1.3 — но не CSP. В коде интерфейса нет `dangerouslySetInnerHTML`, `innerHTML`, `eval` — риск XSS низкий; CSP — второй рубеж. Предложение: `default-src 'self'` с проверкой в браузере.

### Н4 — низкий: `audit.revoked_grant_036` вероятно читают рабочие роли

Пакет 036 создал `audit.revoked_grant_036` и снял права только у `PUBLIC`; по E1 037 право по умолчанию схемы `audit` есть у `dwh_etl` — значит, таблицу 036, скорее всего, читает `dwh_etl` — та же ошибка, что у 037 в E1 (права по умолчанию схемы `audit`). Содержимое — список снятых привилегий `dwh_etl` (без данных и секретов), риск низкий. Проверить на сервере (только чтение) в составе шага 2 аудита; исправление — на решение пользователя.
