# I11 — Источник API (HTTP, cURL, постраничная выдача, JSON/XML)

<sub>Проект плана 24.11.2026. Итерация выбрана пользователем 24.11.2026. Решения А1–А4 и Б1–Б11 — на утверждение; новая задача I11-05 — с согласия пользователя.</sub>

## 1. Задача

Сейчас DWH грузит только из баз PostgreSQL. I11 добавляет источник **API**: объект — это HTTP-запрос, ответ (JSON или XML) превращается в строки и дальше идёт общим путём: маппинг → STG → ODS → витрины, ручной запуск и расписание (I08, I09).

Модель, утверждённая пользователем 03.11.2026 (I03): у источника API есть **только название**; адрес, параметры и учётные данные хранятся **у каждого объекта**, даже если они повторяются. Правило 05.11.2026: исходящие запросы DWH к источникам — **только `SELECT` и `GET`**.

Задачи roadmap:
- I11-01 — HTTP-запрос объекта: адрес, параметры, заголовки, авторизация; секреты на сервере; безопасная проверка запроса.
- I11-02 — импорт и экспорт cURL без выполнения команд оболочки, токены скрыты.
- I11-03 — постраничная выдача, повторы, таймауты, ограничение частоты, ошибки HTTP.
- I11-04 — разбор структуры JSON/XML, путь к массиву, ручные поля и типы; тот же редактор маппинга; версии структуры и остановка при изменении структуры.

**Новое (запрос пользователя 24.11.2026):** чтобы проверить API на настоящих данных, сначала нужен **тестовый API-сервис для `PROCESS_VIEWER`**. Предлагается задача **I11-05 «Тестовый API-сервис PROCESS_VIEWER»** (ID — с согласия).

## 2. Что известно по коду (до описи)

- Контракт адаптеров (`backend/src/dwh_api/connector_contract.py`) уже допускает вид источника `API`; адаптер есть только у PostgreSQL.
- Подключение источника — `meta.source_connection`; в базе вид ограничен `DATABASE`/`FILE`. Для API подключения на уровне источника нет (по модели I03).
- Пароли хранит SecretStore: привязка `secret_store.binding` относится к **источнику** (слот `SOURCE`), привязки к объекту нет — для токена объекта нужен пакет БД.
- Версии настроек объекта — `meta.object_config_version` (пакет 008): поля, ключ, стратегия; HTTP-запроса там нет.
- Шлюз `source_gateway` закрывает только подключения к PostgreSQL; HTTP-шлюза (только `GET`) нет — его планировали вместе с I11.
- Библиотек HTTP в серверном наборе нет (`deploy/requirements-server.txt`); хватит стандартной библиотеки Python (`urllib`, `http.client`, `xml.etree`, `json`).
- `PROCESS_VIEWER` — PostgreSQL `10.1.10.40:5432`, база `process_viewer`, учётная запись `dwh_reader` только на чтение; объекты `app_users`, `services`, `draft` (у двух есть маппинг).

## 3. Решения

### 3.1. Тестовый API-сервис (I11-05)

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| А1 | Где работает сервис | **A** — на сервере DWH отдельной службой `dwh-test-api` (только `127.0.0.1`), снаружи — через nginx по адресу `https://dwh.vtbaze.local/pv-api/` (тот же сертификат УЦ); код в репозитории, доставка выпуском | B — на сервере `PROCESS_VIEWER` (`10.1.10.40`) — ставят владельцы сервера |
| А2 | Откуда данные | **A** — читает базу `process_viewer` своей учётной записью только на чтение (можно ту же `dwh_reader`); пароль — только в `/etc/dwh/test-api.env` на сервере, вводится на сервере | B — искусственные данные без источника |
| А3 | Что умеет сервис | **A** — только `GET`; таблицы `app_users`, `services`, `draft`; вход по токену (`Authorization: Bearer`) и вариант с ключом в заголовке; постраничная выдача двумя способами (`page`/`size` и курсор `next`); ответ JSON или XML (`?format=xml`); отбор `updated_since` для инкремента; режимы проверки ошибок (`429` с `Retry-After`, `500`, медленный ответ) — только по параметру `simulate` | B — только JSON и одна постраничная схема |
| А4 | Токен сервиса | **A** — генерирует инструмент установки на сервере, хранится только в `/etc/dwh/test-api.env`; в DWH вводится в форме объекта (SecretStore) | B — постоянный токен в настройках |

### 3.2. Источник API в DWH

| № | Вопрос | Рекомендация | Другой вариант |
|---|---|---|---|
| Б1 | Где хранится HTTP-запрос объекта | **A** — в версии настроек объекта (рядом с полями и стратегией): адрес, параметры, заголовки, авторизация, постраничная выдача, путь к массиву; публикуется вместе с маппингом | B — отдельная таблица без версий |
| Б2 | Секрет объекта (токен, пароль, ключ) | **A** — SecretStore, привязка к **объекту** (новый слот `OBJECT`, пакет БД); те же журнал, `READ` только по выполняемой заявке (как пакет 026), в интерфейсе не показывается | B — секрет на весь источник |
| Б3 | Методы | **A** — только `GET` (правило 05.11.2026); тело запроса не поддерживается | B — ещё `POST` для поисковых API |
| Б4 | Виды авторизации | **A** — без авторизации, `Bearer`, `Basic`, ключ в заголовке, ключ в параметре адреса | B — плюс OAuth2 client credentials |
| Б5 | Импорт cURL | **A** — разбор строки на сервере без запуска оболочки: адрес, `-G`, `-H`, `-u`, `--data-urlencode`/`-d` с `-G`; заголовки авторизации уходят в секрет и в форме не показываются; экспорт cURL — с `***` вместо секрета | B — без импорта |
| Б6 | Постраничная выдача | **A** — нет / номер страницы и размер / смещение и лимит / курсор из ответа / ссылка «следующая» из ответа или заголовка `Link`; предел страниц на запуск | B — только номер страницы |
| Б7 | Таймауты, повторы, частота | **A** — таймаут 30 с; до 3 повторов на `429`, `5xx` и сетевые ошибки с паузой по `Retry-After` или нарастающей; пауза между запросами (по умолчанию 0); понятные коды ошибок `HTTP_401`, `HTTP_429`, `API_TIMEOUT`, `API_BAD_JSON` | B — без повторов |
| Б8 | Структура JSON/XML | **A** — «Проверить запрос» берёт первую страницу, пользователь выбирает путь к массиву (`data.items`, для XML — путь к элементу), вложенные поля раскладываются в `a.b`, вложенные массивы — текстом JSON; типы предлагаются, пользователь правит; дальше — существующий редактор маппинга; снимок структуры сохраняется, исчезновение поля или смена типа при загрузке — остановка `SOURCE_DRIFT` | B — только плоский JSON |
| Б9 | Инкремент | **A** — как в I07: поле изменения в ответе + параметр запроса с отметкой (`updated_since={{watermark}}`) и перекрытием; иначе — полная загрузка | B — только полная |
| Б10 | Защита исходящих запросов (HTTP-шлюз) | **A** — только `GET`; только `https` (и `http` лишь для адресов из списка); адрес — только из списка разрешённых хостов в настройках сервера (`DWH_HTTP_ALLOWED_HOSTS`); переход на другой хост по перенаправлению запрещён; предел размера ответа; сторож-тест, как у `source_gateway` | B — любые адреса |
| Б11 | Создание источника и объекта | **A** — источник вида «API» в «Администрировании» без подключения; объект API добавляется вручную (имя объекта = код запроса), снимок «из базы» для него не нужен | B — объект создаётся из импорта cURL |

## 4. Шаги до `DONE`

1. **Опись** на сервере (только чтение): `database/diagnostics/i11_api_inventory.sql` — источники и виды подключений, колонки `meta.source_object` и `meta.object_config_version`, объекты и структура `PROCESS_VIEWER`, таблицы STG/ODS, устройство привязки SecretStore.
2. **Утверждение** А1–А4, Б1–Б11 и задачи I11-05.
3. **Тестовый API-сервис** в песочнице: `tools/test_api/` (служба на стандартной библиотеке Python), установка `tools/server/dwh_test_api_setup.py` (план / `--apply` / `--check`: служба, nginx, токен, пароль чтения вводится на сервере), тесты.
4. **Тестовый сервис на сервере:** выпуск, установка, проверка с сервера и с ПК (JSON, XML, страницы, токен, `429`).
5. **Песочница DWH:** пакет 033 (HTTP-запрос в версии объекта, слот `OBJECT` в SecretStore с журналом и `READ` по заявке, вид источника `API`; откат), E0; HTTP-шлюз, адаптер API, разбор cURL, проверка запроса и структуры, движок загрузки (страницы, повторы, инкремент, `SOURCE_DRIFT`), API и экран «HTTP-запрос» в «Маппинге»; тесты, сборка, ESLint 0/0, браузер, сквозная проверка с тестовым сервисом.
6. **Выпуск, E1 и E2 пакета 033** на сервере (каждый — с разрешения пользователя).
7. **Приёмка на сервере:** источник `PROCESS_VIEWER_API`; объект `services` (JSON, курсор) и `app_users` (XML, номер страницы) через импорт cURL; токен не виден в интерфейсе, журнале и cURL-экспорте; загрузка STG → ODS `SUCCESS`, строки совпадают с загрузкой из базы; инкремент; `429` — повтор и успех; неверный токен — `HTTP_401` с понятной причиной; хост не из списка — отказ; запуск по расписанию. Реестр; подтверждение — `DONE`.

## 5. Не входит

- Методы кроме `GET`, тело запроса, OAuth2 (Б3, Б4 — варианты B).
- Файлы JSON/XML из папки — I12.
- Тестовый сервис — только для проверки; в эксплуатацию как API `PROCESS_VIEWER` не передаётся.
